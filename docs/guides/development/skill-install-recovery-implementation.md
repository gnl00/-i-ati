# 技能安装、残缺恢复与启动失败报告实施指导

日期：2026-09-03。状态：实现与独立复核完成，本机 pdf 副本已恢复。

## 已确认问题

导入源与安装副本是两个目录：配置中的 `<source>/pdf/SKILL.md` 完整存在，
ATI 扫描的 `<userData>/skills/pdf/SKILL.md` 缺失。真实目录验证和修改前 HEAD
对照均得到相同结果。`SkillPathResolver` 和共享 `WorkspacePathBoundary`
保持原代码，本次工作沿技能安装与导入链路展开。

在临时目录复制残缺副本，调用真实 `SkillService.importSkillsFromFolder()`，
可稳定复现：扫描返回 `PATH_NOT_FOUND`，导入汇总返回
`Skill "pdf" already installed`。已安装列表跳过残缺项，安装器又按目录
存在判定冲突，形成恢复缺口。

`SkillInstaller` 当前覆盖流程先删除旧目录再直接复制，复制失败或进程退出
会留下半成品。启动配置包含三个来源时，`Promise.allSettled` 发起三次
并发扫描；`summary.failed` 作为成功返回值被启动层遗漏。

## 目标与范围

- 目录、单文件、URL 内容和解压后目录统一经过安全发布流程。
- 已安装的完整技能在准备新版本期间持续保留；失败后保留可恢复数据。
- 从用户已配置的有效来源恢复同名残缺副本，保留残缺目录备份。
- 同一进程内的安装、导入与删除依次修改安装根，避免名称决策和发布竞争。
- 启动导入报告来源级异常及逐技能 `failed`；一个来源失败后继续后续来源。
- 同步缓存、技能目录扫描规则、测试及当前架构说明。

保留既有技能路径约束、完整技能同名冲突处理、来源匹配、工具契约和 UI。
实现范围限定为技能安装与恢复；工作区绝对路径、模型配置和评测保持原状态。

## 实施约束

### 准备与发布

1. 读取并校验源文件、名称与目标路径。保留 `SkillPathResolver` 对链接和
   canonical containment 的约束。目标目录、临时目录及备份目录必须位于
   可信安装根；符号链接目标和不明文件类型保持明确失败。
2. 在与安装根同一文件系统的内部暂存目录完成复制或内容写入，并写入来源
   信息。发布前重新读取暂存的 `SKILL.md`、解析元数据，验证复制后的链接
   语义；准备阶段的异常只清理本次暂存目录。
3. 首次安装通过目录 rename 发布。覆盖时先把旧版本移动到保留位置，再
   把完整候选发布到目标；发布异常回滚旧版本，回滚异常保留备份并报告
   可恢复位置。最终发布成功后再更新缓存。
4. 目录覆盖涉及两次 rename，需要明确进程中断窗口。采用最小的可识别
   备份/事务记录，保证重新初始化时可以恢复已移动且尚未发布的旧版本。
   禁止把两次 rename 描述为跨平台单操作原子交换。恢复过程只处理本实现
   创建且校验通过的记录，活动安装记录保持隔离。
5. 保留普通文件权限、资源文件与内部链接语义。源目录与安装目标重合、
   根目录别名和不明符号链接需要显式处理，避免移动/清理源文件。

### 残缺识别与恢复

- 只把已确认的入口缺失、非法入口类型或元数据损坏作为残缺状态。权限
  错误、读取失败和链接越界保留各自失败原因，避免误判为可覆盖内容。
- 对完整技能延续来源匹配和重名改名规则；恢复同名残缺技能时先完整准备
  候选，再保留旧目录备份后替换。原始残缺文件保留供用户核对。
- 来源信息存在时尊重来源归属；来源不同或无法安全判定的冲突使用现有
  改名/明确失败行为。对于缺少入口和来源信息的历史半成品，同名、已配置
  来源可执行保留备份的重建。
- 内部暂存、备份及记录目录从已安装列表、缓存校验和导入收集器排除；
  只使用明确保留的内部名称，避免广泛忽略用户目录。

### 并发与启动报告

- 复用现有入口，用简单的进程内 Promise 队列串行化会修改技能根的服务
  操作；拒绝后的队列继续可用。读取调用保持可重入，防止导入等待自身。
- 启动按配置顺序导入，后续来源读取前一次导入后的状态，保持确定的
  重名行为。每个来源的异常及 `summary.failed` 都产生可定位的错误日志。
- 保留现有 `SkillImportSummary` 字段。恢复信息可通过最小兼容字段或日志
  表达，保证失败原因、源目录和目标身份可追踪，避免输出技能内容及密钥。
- 明确进程内队列的边界。跨进程 CLI/Desktop 同写及恢复记录的识别必须
  避免相互删除活动暂存；需要额外跨进程能力时先报告具体风险和最小方案。

## 代码落点

- `src/main/services/skills/SkillInstaller.ts`：共享准备与发布入口。
- `src/main/services/skills/SkillImporter.ts`：残缺恢复与完整同名冲突判定。
- `src/main/services/skills/SkillCache.ts`、`SkillCollector.ts`：内部目录过滤、
  缓存失效及恢复后读取。
- `src/main/services/skills/SkillService.ts`：操作串行化、初始化及汇总报告。
- 必要时新增一个职责明确的安装辅助模块，优先标准库函数。
- 对应 `__tests__`、现行技能架构说明、文档索引与必要 ADR。

实现前阅读以上文件的调用者、导出和现有测试。工作区包含 CLI 与工作区
工具契约等既有未提交改动，保持它们原样。Luna 负责上述技能实现与测试；
主 agent 负责独立复核、基线对照和本机 pdf 副本恢复。

## 验收

1. 先运行失败回归：残缺副本可恢复、复制异常保留完整旧版本、发布异常
   回滚、启动记录 `summary.failed`。记录改前失败与改后通过证据。
2. 目录及内容安装均在完整校验后发布；正常更新、名称冲突、来源匹配
   延续既有行为。内部链接安全语义、外部链接和权限错误分别覆盖。
3. 模拟遗留备份恢复；活动记录保护；内部目录在已安装列表中不可见。
4. 验证并发导入/安装确定性、拒绝后队列可用及来源失败后继续。
5. 运行技能相关 Vitest、主进程边界/文档路径/架构检查、Node 类型检查、
   改动行 lint。记录既有基线错误，避免全仓格式修改。
6. 在临时用户目录重现本机残缺 pdf，执行真实服务恢复并验证 SKILL.md、
   来源信息、脚本完整、旧副本备份以及后续导入成功。测试使用本地文件，
   保持零模型 API 调用。
7. 本机恢复先备份安装副本，再通过已验证的相同流程从用户源目录恢复；
   仅操作 pdf 副本及本次备份，源目录保持原样。记录备份位置及读取结果。

## 实施与验证记录

实现由 Luna（max）完成主体代码，主 agent 完成独立回归与边界修正：

- `SkillInstallation.ts` 统一暂存、发布记录、回滚、遗留恢复与安装根互斥。
  两次目录 rename 之间的中断通过记录和旧目录备份恢复。陈旧锁回收使用
  独占标记并重新检查所有者；活动、权限不可判定、损坏的所有者记录保持
  保护。记录路径必须是保留根下的直接子项，并通过 canonical 校验。
- `SkillInstaller.ts` 的目录、文件、URL 内容及压缩包共用发布流程；
  `SkillImporter.ts` 支持同来源或历史无来源半成品的备份重建，保留其他
  来源的改名规则。来源信息读取失败、非法链接和权限错误保持显式失败。
- `SkillCache.ts` 与恢复流程复用完整性检查，缓存版本升为 5；安装根中的
  `.skill-staging`、`.skill-backups`、`.skill-transactions`、`.skill-lock`
  和历史 `.tmp` 从列表及收集器排除。
- `SkillService.ts` 串行化当前进程的修改操作。启动即使没有配置导入目录
  也执行遗留恢复；每个来源依次导入并报告 `summary.failed`。
- [ADR-0020](../../decisions/0020-skill-install-recovery.md) 和
  [Skills](../../integrations/skills.md) 同步了现行安装契约。
